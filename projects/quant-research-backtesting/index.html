CASE 07 / ENGINEERING IN DETAIL

量化策略研究与回测框架

先把信号、费用和资金变化对上，再看回测结果。

个人研究 · AI 协作 · 模拟回测原型

问题与约束

这是与 AI 协作完成的个人研究原型。LEAN / C# 计算信号，Python 独立模拟成交和资金变化，再逐笔核对费用与风险规则的影响。研究重点是找出计算差异、保留实验条件，不以单份收益曲线判断策略有效。

核心链路简化示意

以下图示为技术思路的简化表达。

  1. 01 / 行情与信号LEAN / C# 计算
  2. 02 / 独立账本Python 模拟成交
  3. 03 / 成本与风险费用、现金与约束
  4. 04 / 交叉核对逐笔明细与研究报告

架构取舍与实现

01

信号计算与资金账本分别核对

难点只看引擎最终统计，很难区分问题来自信号、成交假设还是资金计算。

方案由 LEAN / C# 导出结构化策略信号，独立 Python 账本消费信号并模拟资金与成交路径，再使用独立窗口计算逐行核对。

考虑出现差异时，可以分别检查信号窗口、成交假设和资金计算；信号计算阶段不下单。

02

风险判断使用扣费后净权益

难点报告扣了费用，实际现金和风险判断却没扣，会使研究结论出现偏差。

方案区分交易权益、净权益、实际扣款和收益归因，将手续费、滑点、资金费与结算纳入账本，风险控制使用扣费后净权益。

考虑费用会改变后续可用资金和风险判断，逐笔记录可用于检查漏扣、重复扣费和归因错误。

03

保存输入、代码和逐笔结果

难点输入、参数和代码变化后，如果只保留汇总图表，就难以解释结果差异。

方案保存逐笔交易、决策原因、费用与风险记录，用脚本串联信号校验、回测和账本验收，并校验输入、代码与输出哈希。

考虑重新运行时可以核对数据与代码版本，再从交易、费用和决策明细中查找结果差异。

这套设计解决了什么

将策略信号、模拟成交和资金账本分开核对，并用逐笔记录与哈希记录各次实验。

验证关注点

  • 策略信号与账本逐行核对后，是否存在遗漏、偏移或重复消费？
  • 费用扣除和风险暂停是否真正改变可用现金、持仓及后续入场？
  • 冻结同一组输入、代码和参数，能否复现明细与汇总结果？

研发范围

AI 协作完成的个人研究原型，覆盖信号计算、独立资金账本、风险规则、结果核对与 HTML 研究报告。

当前阶段

当前为研究与模拟回测阶段，未接入券商账户或实盘下单；回测结果不代表未来收益。

  • 可复现研究
