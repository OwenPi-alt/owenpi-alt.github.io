CASE 07 / ENGINEERING IN DETAIL

Dify 运营自助答疑

运营常问的数据和状态，尝试让机器人直接查出来。

奇富科技 · 参与项目建设 · 2025.05 — 2026.03

问题与约束

运营经常需要研发协助查数据、查状态和查规则。问题来自日常业务，但答案分散在接口和系统中。项目通过 Dify 将自然语言问题组织成可执行的查询流程，并接入 360Teams，让运营能够在熟悉的沟通入口直接发起提问。

核心链路简化示意

以下图示为技术思路的简化表达。

  1. 01 / 运营提问360Teams 机器人
  2. 02 / 理解问题意图识别与参数抽取
  3. 03 / 业务查询调用已有内部接口
  4. 04 / 组织回复返回业务查询结果

架构取舍与实现

01

把自然语言拆成执行步骤

难点运营表达的是业务问题，内部接口需要的是明确的操作类型和参数。

方案项目使用 Dify 编排意图识别、参数抽取、内部接口调用与结果回复，将一句提问分解为具有不同职责的处理步骤。

价值让问题理解与业务执行能够分别检查，便于辨认偏差发生在意图、参数还是查询结果。

02

让业务接口承担事实查询

难点数据、状态和规则有各自的来源，需要把语言理解和实际业务信息连接起来。

方案工作流将提取出的业务参数用于已有内部接口调用，再围绕返回结果组织回复，面向运营日常查询需求形成问答路径。

价值模型负责连接表达与流程，业务信息仍有对应查询来源，使回答可以回到具体接口结果核对。

03

把能力放进已有工作入口

难点查询工具即使可用，如果入口分散，运营仍需要在多个系统之间寻找操作路径。

方案项目接入 360Teams 机器人，供运营直接提问，将数据查询、状态确认和规则答疑的工作流带入日常沟通工具。

价值缩短从提出问题到发起查询的操作路径，让自动化能力围绕实际工作习惯组织。

工程价值

将高频业务查询组织成可执行工作流，让自然语言入口、内部接口与运营工作场景连接起来。

验证关注点

  • 问题表达不完整或参数缺失时，是否能够识别需要补充的信息？
  • 接口权限、异常响应和空结果，是否纳入上线前的验收范围？
  • 回复中的数据与业务接口返回值是否一致，能否回查对应来源？

我的职责

参与运营自助查询项目建设，围绕运营日常的数据、状态与规则查询场景协作推进。

技术与主题

  • Dify
  • 意图识别
  • 参数抽取
  • 业务 API
  • 工作流编排
  • 360Teams
