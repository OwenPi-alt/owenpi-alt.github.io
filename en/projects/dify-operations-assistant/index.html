Dify Self-Service Assistant for Operations

The aim was to let operations ask a bot for the data and status checks they routinely needed.

Qifu Technology (奇富科技) · Project contributor · 2025.05 — 2026.03

Context and constraints

Operations staff frequently needed engineering help to look up data, statuses, and business rules. Answers were spread across internal APIs and systems. The project used Dify to turn natural-language questions into executable query workflows and brought them into 360Teams, where staff could ask through an existing communication tool.

Core workflow

Design decisions and implementation

01

Turn a question into distinct execution steps

ChallengeOperations staff describe a business question; internal APIs require a specific operation and explicit parameters.

ApproachThe project used Dify to orchestrate intent recognition, parameter extraction, internal API calls, and response assembly as separate workflow steps.

ValueAllows language understanding and business execution to be inspected separately, helping locate errors in intent, parameters, or query results.

02

Use business APIs as the source of facts

ChallengeData, statuses, and rules each have their own sources. Language understanding must connect to those business facts.

ApproachWorkflows pass extracted business parameters to existing internal APIs and compose replies from the returned results, covering routine operations queries.

ValueConnects natural-language requests to executable queries while keeping each answer tied to a result that can be checked.

03

Bring the workflow into an existing work channel

ChallengeEven a usable query tool adds friction if staff must search across systems to find the right entry point.

ApproachThe project integrated a 360Teams bot so operations staff could ask questions directly, bringing data lookups, status checks, and rule queries into their everyday communication tool.

ValueShortens the path from asking a question to starting a query and fits the workflow around existing work habits.

Engineering value

Organizes common business queries into executable workflows, connecting a natural-language entry point with internal APIs and everyday operations work.

Validation focus

  • Can the workflow identify information that needs clarification when a question or its parameters are incomplete?
  • Are API permissions, error responses, and empty results included in pre-release acceptance checks?
  • Does the answer agree with the business API response, and can that source be checked?
