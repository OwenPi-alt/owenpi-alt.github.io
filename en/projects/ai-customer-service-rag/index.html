AI Customer Support & Knowledge Retrieval

I contributed to support-message processing and routing, including context, retries, and task state.

Qifu Technology (奇富科技) · Contributor to message processing and routing

Context and constraints

Support inquiries need ticket context to choose among clarification, status queries, knowledge retrieval, and human handoff. The platform retains model calls and citations for answer investigation and operational feedback. My contributions were in message processing and routing; the following also describes the wider workflow those modules participate in.

Design decisions and implementation

01

Persist processing records before calling the model

ChallengeMessage intake and model calls run at different speeds. After a failure, the system also needs to know which state the task reached.

ApproachThe system receives messages through RabbitMQ, persists processing records, and invokes the model asynchronously. Duplicate-message checks, state-conditioned retries, and timeout cleanup manage the task lifecycle.

ReasoningAfter a model-call failure, task records help determine whether to retry or clear a timed-out state, beyond the response from a single request.

02

Organize context and routing by support ticket

ChallengeClassifying only the latest sentence can miss the support ticket’s background and differences between business scenarios.

ApproachThe routing pipeline combines rules, model classification, and knowledge retrieval in stages, with bounded context organized by support ticket. Routes support clarification, status queries, and human handoff.

ReasoningRouting can use ticket history while retaining stage-by-stage decisions, helping locate classification or retrieval errors.

03

Retain citations, prompts, and model-call details

ChallengeThe final reply alone cannot explain its source or why a particular model call produced an unsuitable result.

ApproachThe system integrates the Bailian knowledge base and uses retrieval scores and thresholds to inform replies. It retains routes, cited passages, prompt versions, model and token information, and operational feedback.

ReasoningAn answer can be checked against its cited passages, prompt, and model call to investigate whether an issue arose in retrieval or generation.

What the design addresses

Contributed to message handling and scenario routing, using ticket context and handling duplicate submissions, failed attempts, and timed-out tasks.

Validation focus

  • Do duplicate messages, timed-out tasks, and failed retries follow the correct state-dependent paths?
  • Do missing knowledge, retrieval failures, and insufficient context lead to appropriate routing or feedback?
  • Can an answer be traced to its knowledge citations, prompt version, and model call?

My contribution

Contributed to support-message processing and routing, using business context to distinguish scenarios. Work included failure retries, timeout-state cleanup, and duplicate-submission controls.
